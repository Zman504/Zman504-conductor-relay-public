# Agent handoffs

Use a handoff when work moves between agents, a lane becomes blocked, or a
reviewer needs a concise evidence packet. A handoff is context, not authority:
the receiving agent must still follow the project instructions and lane rules.

Each handoff should include:

- originating and receiving lanes;
- the exact files and claim state;
- the goal and boundary of the work;
- changes or findings, with evidence and commands run;
- known limitations or blockers; and
- one concrete next action.

Create the handoff on an unclaimed path, using
[templates/handoff.md](templates/handoff.md). Link it from the relevant lane
row or task discussion. Do not paste credentials, tokens, private data, or
unnecessary command output into a handoff.
